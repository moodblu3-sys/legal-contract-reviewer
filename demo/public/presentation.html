🤖 Box AI が行うこと

  • 稟議書の内容を読み取り、カテゴリを自動分類（設備投資/採用/外注 等）
  • 申請金額を抽出し、承認ルートの分岐条件に使用
  • 添付書類の有無をチェック（見積書・仕様書の添付漏れ検知）
  • 分類結果をメタデータに記録 → 監査証跡として活用

🔀 Box Relay が行うこと

  • 金額に応じた承認ルートの自動選択（100万未満:部長 / 1000万未満:本部長 / それ以上:役員）
  • 承認者へ自動通知（メール + Box通知）
  • 承認・差戻しのステータス管理と可視化
  • SLAベースのリマインダー自動送信

Box単体 vs 外部AI の使い分け

UC1・UC2はBox完結、UC3は将来フェーズで外部AI活用
ユースケース 実現方式 フェーズ 技術選定の根拠
UC1: 契約書の条項チェック Box AI Phase 1 契約書の内容がBox外に出ない。AI Ask + Extract Structured でカバー可能。
UC1: 構造化データ抽出 Box AI Phase 1 Box AI Extract Structured API で日本語フィールドも正確に抽出。
UC2: 稟議書の自動分類 Box AI Phase 2 AI Ask でカテゴリ・金額・添付有無を自動判定。Metadata に書戻し。
UC2: 承認ワークフロー Box AI + Relay Phase 2 ノーコードで承認フロー構築。AI分類結果に基づきルート自動分岐。
UC3: 社内問い合わせBot 外部LLM + Box API Phase 3 対話型UIには外部LLMが必要。MCP経由でBoxコンテンツを参照し回答生成。
UC3: 全社ナレッジ検索 外部RAG Phase 3 部門横断の意味検索・対話にはRAG基盤が必要。Box APIでコンテンツを安全に取得。

設計方針： Phase 1・2 はBox単体で完結（外部AI不要）。機密性の高い文書処理はBox AI内で完結させ、 Phase 3 で対話・推論など高度なAI機能が必要な場面でのみ外部LLMを補完的に活用します。
